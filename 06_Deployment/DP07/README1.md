# 2. 각 섹션 체크포인트의 답변

## 2.1 프로젝트 개요: 한국어 챗봇 서비스 설계

### ✅ 체크포인트 1

**Day 5(정형 데이터)와 Day 7(텍스트 생성)에서 전처리가 어떻게 다릅니까?**

Day 5의 정형 데이터에서는 결측치 처리, 범주형 데이터 인코딩, 정규화 등의 방법으로 데이터를 모델 입력에 적합한 형태로 변환한다.

Day 7의 텍스트 데이터에서는 토크나이저를 이용하여 자연어 문장을 토큰으로 나누고 모델이 처리할 수 있는 Token ID로 변환한다.

즉,

- 정형 데이터 → 데이터 값 정리 및 변환 → 모델 입력
- 텍스트 → 토큰화 → Token ID → 모델 입력

### ✅ 체크포인트 2

**Hugging Face Transformers 라이브러리의 역할은 무엇입니까?**

Hugging Face Transformers는 GPT, BERT와 같은 사전학습된 Transformer 모델과 토크나이저를 쉽게 불러와 사용할 수 있도록 지원하는 라이브러리이다.

이번 프로젝트에서는 한국어 GPT 모델과 토크나이저를 로드하고 챗봇의 텍스트 응답을 생성하는 데 사용하였다.

## 2.2 모델 준비: Hugging Face 한국어 GPT 모델 로드

### ✅ 체크포인트 1

**토크나이저의 `encode()`와 `decode()`는 각각 어떤 변환을 수행합니까?**

`encode()`는 사람이 입력한 텍스트를 모델이 처리할 수 있는 Token ID 형태의 숫자로 변환한다.

`decode()`는 모델이 생성한 Token ID를 다시 사람이 읽을 수 있는 텍스트로 변환한다.

### ✅ 체크포인트 2

**`model.generate()`의 `temperature` 파라미터는 생성 결과에 어떤 영향을 줍니까?**

Temperature는 다음 토큰을 선택할 때 생성 결과의 다양성과 무작위성에 영향을 준다.

- 낮은 Temperature → 상대적으로 일관되고 보수적인 응답
- 높은 Temperature → 보다 다양한 응답
- 지나치게 높은 Temperature → 문맥과 관련성이 낮거나 불안정한 응답이 생성될 가능성 증가

### ✅ 체크포인트 3

**멀티턴 대화에서 이전 대화 기록을 프롬프트에 포함하는 이유는 무엇입니까?**

모델이 이전 대화의 문맥을 참고하여 현재 질문에 답할 수 있도록 하기 위해서이다.

이전 사용자 메시지와 챗봇 응답을 함께 전달하면 앞선 대화를 바탕으로 후속 질문에 응답할 수 있다.

## 2.3 FastAPI 백엔드: 챗봇 추론 API

### ✅ 체크포인트 1

**`ChatRequest`의 `messages`가 리스트인 이유는 무엇입니까?**

사용자 질문과 챗봇 응답 등 여러 개의 메시지를 순서대로 전달하기 위해서이다.

이를 통해 이전 대화 내용을 함께 전달하여 멀티턴 대화를 구현할 수 있다.

### ✅ 체크포인트 2

**서버가 대화 기록을 저장하지 않고, 클라이언트가 매번 전체 기록을 보내는 이유는 무엇입니까?**

서버가 사용자별 상태를 직접 저장하지 않으면 각 요청을 독립적으로 처리할 수 있어 서버 구조가 단순해진다.

또한 여러 서버로 서비스를 확장할 때 사용자별 상태 관리 부담을 줄일 수 있다.

### ✅ 체크포인트 3

**`max_new_tokens`을 너무 크게 설정하면 어떤 문제가 발생할 수 있습니까?**

- 응답 생성 시간이 증가할 수 있다.
- 메모리 사용량이 증가할 수 있다.
- 불필요하게 긴 답변이 생성될 수 있다.
- 서버 부하가 증가할 수 있다.
- 동시 요청 처리 성능이 저하될 수 있다.

## 2.4 Streamlit UI: 채팅 인터페이스

### ✅ 체크포인트 1

**`st.chat_message`와 `st.chat_input`은 각각 어떤 역할을 합니까?**

`st.chat_message`는 사용자와 챗봇의 메시지를 채팅 형태로 화면에 표시한다.

`st.chat_input`은 사용자가 챗봇에게 보낼 메시지를 입력하는 입력창을 제공한다.

### ✅ 체크포인트 2

**`st.session_state["chat_messages"]`에 대화 기록을 저장하는 이유는 무엇입니까?**

Streamlit이 다시 실행되더라도 동일한 사용자 세션에서 이전 대화 내용을 유지하기 위해서이다.

이를 통해 멀티턴 대화를 구현할 수 있다.

### ✅ 체크포인트 3

**"대화 초기화" 버튼이 `st.rerun()`을 호출하는 이유는 무엇입니까?**

대화 기록을 삭제한 후 변경된 상태를 UI에 즉시 반영하기 위해서이다.

`대화 초기화 → 대화 기록 삭제 → st.rerun() → 빈 채팅 화면 표시`
