# Day 6 — 인증 및 미디어 처리 기초

## 1. API 보안의 필요성: 왜 아무나 호출하면 안 되는가?

### ✅ 체크포인트

**Q. 인증 없는 API가 위험한 이유를 두 가지 이상 설명하세요.**

1. 인증이 없으면 허가되지 않은 사용자가 API를 무단으로 호출할 수 있습니다.
2. ML 추론 API가 반복적으로 호출되면 CPU/GPU, 메모리 등의 서버 자원이 과도하게 사용될 수 있습니다.
3. 악의적인 대량 요청으로 서버 장애나 운영 비용 증가가 발생할 수 있습니다.

**Q. API Key 방식이 ML 추론 API에 적합한 이유는 무엇입니까?**

API Key 방식은 구현이 비교적 간단하면서 요청자의 접근 권한을 확인할 수 있습니다.  
클라이언트가 HTTP Header에 API Key를 전달하고, 서버는 해당 Key가 올바른 경우에만 모델 추론을 수행하도록 제한할 수 있습니다.


---

## 2. API Key 인증 구현: Header 기반 인증

### ✅ 체크포인트

**Q. `Header(None)`에서 `None`은 어떤 상황에서 `x_api_key`에 들어갑니까?**

클라이언트가 요청 Header에 `X-API-Key`를 전달하지 않았을 때 `x_api_key`에 `None`이 들어갑니다.  
이를 이용하여 API Key가 누락된 요청을 확인하고 차단할 수 있습니다.

**Q. `Depends(verify_api_key)`를 엔드포인트에 추가하면 요청 처리 흐름이 어떻게 바뀝니까?**

엔드포인트의 실제 처리 로직이 실행되기 전에 `verify_api_key()`가 먼저 실행됩니다.  
API Key가 올바르지 않으면 인증 단계에서 요청을 차단하고, 올바른 경우에만 이미지 처리와 모델 추론 단계로 진행합니다.

**Q. 인증 실패 시 반환하는 HTTP 상태 코드 401의 의미는 무엇입니까?**

`401 Unauthorized`는 요청에 필요한 인증 정보가 없거나 유효하지 않아 서버가 요청을 허용하지 않았음을 의미합니다.

## 3. 비정형 데이터의 세계: 이미지와 텍스트 입력 처리

FastAPI의 파일 업로드 기능을 이용하여 이미지와 같은 비정형 데이터를 API 입력으로 전달하도록 구성하였습니다.

이미지는 `/predict/image` 엔드포인트를 통해 전달되고, 서버에서 모델이 처리할 수 있는 형태로 전처리한 후 추론에 사용합니다.


---

## 4. 파일 업로드와 안전장치: 크기 제한, 이미지 리사이징

### ✅ 체크포인트

**Q. `UploadFile`과 Base64 방식의 핵심 차이는 무엇입니까?**

`UploadFile`은 파일을 `multipart/form-data` 방식으로 직접 전송합니다.  
Base64 방식은 이미지 등의 바이너리 데이터를 문자열로 변환한 후 JSON 등에 포함하여 전달합니다.

`UploadFile`은 별도의 Base64 변환 과정이 필요하지 않고 파일명, Content-Type 등의 정보를 쉽게 처리할 수 있다는 장점이 있습니다.

**Q. `file.content_type`으로 타입을 검증하는 이유는 무엇입니까?**

업로드된 파일이 서버에서 허용하는 이미지 형식인지 확인하기 위해 사용합니다.  
예상하지 않은 파일 형식이 이미지 추론 API로 전달되는 것을 제한할 수 있습니다.

**Q. 파일 크기를 제한하지 않으면 어떤 문제가 발생할 수 있습니까?**

지나치게 큰 파일이 업로드되면 서버의 메모리와 CPU 등의 자원이 과도하게 사용될 수 있습니다.  
반복적인 대용량 파일 요청은 응답 지연이나 서버 장애의 원인이 될 수 있으므로 파일 크기 제한이 필요합니다.

## 5. 추론 파이프라인: 전처리 → 모델 호출 → 후처리

이미지 추론 API의 전체 처리 과정은 다음과 같습니다.

`이미지 입력 → API Key 인증 → 파일 검증 → 이미지 전처리 → 모델 추론 → 결과 후처리 → JSON 응답`

MNIST 이미지의 경우 모델 입력 형식에 맞도록 이미지를 28×28 크기의 그레이스케일 이미지로 변환하여 모델에 전달합니다.

## 6. 수행내역

### 6.3 인증 없이 요청 → 401

API Key를 포함하지 않고 `/predict/image` 엔드포인트에 POST 요청을 전송하였습니다.

서버는 API Key가 없음을 확인하고 HTTP `401 Unauthorized`를 반환하였습니다.

API Key가 없는 요청에 대해 HTTP 401 Unauthorized가 반환되어 인증되지 않은 요청이 차단되는 것을 확인하였습니다.

### 6.5 올바른 키 + MNIST 이미지 → 성공

올바른 API Key를 Header에 포함하여 MNIST 테스트 이미지를 `/predict/image` 엔드포인트에 전송하였습니다.

실행 결과 테스트 이미지의 정답은 `7`이었으며, 모델 역시 `7`로 예측하였습니다.

HTTP 상태 코드 `200`이 반환되었으며 예측 결과는 다음과 같이 확인되었습니다.

- 테스트 이미지 정답: `7`
- 상태 코드: `200`
- 예측 label: `7`
- confidence: `1.0`

이를 통해 `API Key 인증 → 이미지 입력 → 모델 추론 → 결과 반환` 과정이 정상적으로 동작함을 확인하였습니다.

### 6.8 Swagger UI에서 테스트

FastAPI 서버 실행 후 Swagger UI에서 API 엔드포인트가 정상적으로 등록된 것을 확인하였습니다.

이를 통해 FastAPI 서버에서 상태 확인 API와 이미지 추론 API가 정상적으로 노출되고 있음을 확인하였습니다.

### ✅ Day 6 최종 체크포인트

**Q1. API Key 인증이 없으면 어떤 위험이 있습니까? (두 가지 이상)**

인증되지 않은 사용자가 API를 무단으로 호출할 수 있으며, 반복적인 추론 요청으로 CPU/GPU와 메모리 등의 서버 자원이 과도하게 사용될 수 있습니다. 또한 악의적인 대량 요청으로 서버 장애나 운영 비용 증가가 발생할 수 있습니다.

**Q2. `Depends(verify_api_key)`는 엔드포인트 실행 전에 어떤 일을 합니까?**

요청 Header에 포함된 API Key가 올바른지 먼저 검사합니다. 인증에 실패하면 `401 Unauthorized`를 반환하여 요청을 차단하고, 인증에 성공한 경우에만 엔드포인트의 실제 처리 로직을 실행합니다.

**Q3. `UploadFile` 방식이 Base64보다 편리한 점은 무엇입니까?**

이미지를 Base64 문자열로 변환하지 않고 파일 형태로 직접 전송할 수 있습니다. 또한 FastAPI에서 파일명과 Content-Type 등의 파일 정보를 쉽게 처리할 수 있습니다.

**Q4. 파일 업로드 시 크기 제한을 하지 않으면 어떤 문제가 생깁니까?**

대용량 파일이나 반복적인 파일 업로드로 서버의 메모리와 CPU 자원이 과도하게 사용될 수 있으며, 응답 지연이나 서버 장애가 발생할 수 있습니다.

**Q5. 이미지를 28x28 그레이스케일로 변환하는 이유는 무엇입니까?**

사용한 MNIST 모델의 입력 형식이 28×28 크기의 그레이스케일 이미지이기 때문입니다. 입력 이미지를 모델이 학습할 때 사용한 형식과 동일하게 맞추어 정상적으로 추론할 수 있도록 전처리합니다.
